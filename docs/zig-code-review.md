# Ревью текущего Zig-кода (июнь 2026)

Снимок состояния `zig/src/` на момент: ассемблер работает сквозняком
(preprocess → tokenize → parse → emit), симулятор — фундамент (5.0 в
[zig-plan.md](zig-plan.md)). Здесь — что уже хорошо и что чинить, по модулям.

---

## Сквозное (про весь код сразу)

**Хорошо:**
- **Zero-copy везде.** Токены, операнды, имена меток — срезы в исходник, ни
  одной лишней копии строки. Это «тот самый» Zig-way, который в C# не делали.
- **Дисциплина аллокаций.** Везде явный allocator, у структур `deinit`, тесты
  на `std.testing.allocator` — утечки ловятся бесплатно в каждом тесте.
- **Тесты в каждом модуле** и агрегатор в `main.zig` (`test { _ = @import… }`).
- Идиоматичный новый std: `std.Io` 0.16, `ArrayList.empty` + allocator в
  методах, `StaticStringMap.initComptime` для мнемоник.
- Комментарии объясняют «почему» (предекод, индекс метки) — читать приятно.

**Чинить:**
- ⚠️ **Лайфтайм-ловушка №1:** `Program`/`Statement`/`labels` держат срезы в
  preprocessed-текст. Освободишь текст раньше программы — use-after-free,
  и компилятор не спасёт. Минимум — задокументировать у `parse()`/`build()`:
  «source должен жить дольше результата». (Вариант на потом: arena на весь
  пайплайн.)
- **Ошибки без координат.** Токены несут `line`/`column`, но парсер их
  выбрасывает: наружу уходит голый `error.UnexpectedToken`. Для тулчейна
  диагностика «файл:строка:колонка: что не так» — половина ценности.
  Достаточно возвращать рядом с ошибкой структуру-диагностику.
- Файл `emit/Emmiter.zig` — опечатка в имени (`Emitter`). Переименовать,
  пока на него ссылаются два файла, а не двадцать.

## Tokenizer.zig

**Хорошо:**
- Чистый конечный автомат с `peek`/`advance`, читается сверху вниз.
- Снятие неоднозначности `+`/`-` (условие vs знак числа) — по тому же
  правилу, что `Tokenizer.cs`: знак + цифра = число, иначе condition.
- `line`/`column` уже считаются (задел под диагностику).

**Чинить:**
- ⚠️ **Незнакомый символ молча проглатывается** (`else => _ = self.advance()`).
  Для подсветки в IDE это ок, для ассемблера — нет: `mov acc, 1` с запятой
  тихо превратится в валидный код. Нужен токен/ошибка `invalid`.
- **Поддержан только `#`-комментарий** — `;` и `/* */` это наш extended
  syntax, отложены сознательно. Но сейчас `;` молча съедается else-веткой,
  а `/* */` превращается в identifier'ы — то есть файл с ними «работает»
  и выдаёт мусор. Пока не реализовано — пусть будет ошибкой (решается тем
  же `invalid`-токеном из пункта выше).
- `\r` (CRLF-файлы) выживает только случайно — через ту же else-ветку.
  Лучше явно: `\r` = whitespace.
- Мелочь: `line` стартует с 1, `column` с 0 — выбери одну конвенцию.

## Parser.zig

**Хорошо:**
- `Mnemonic`-enum + comptime-мапа вместо строк — дальше по конвейеру строки
  мнемоник не существуют. Это ключевое отличие от C# (там строки до конца).
- `Statement = union(enum)` — ровно тот AST из плана, плоский и честный.
- Случай «метка и инструкция на одной строке» учтён и покрыт тестом.

**Чинить:**
- **Число операндов не проверяется:** `mov` без операндов или `jmp a b c` парсятся
  молча. По плану это уедет в `build()` симулятора (шаг 5) — ок, но тогда
  и `assemble` должен прогонять ту же проверку, иначе эмиттер выпустит
  мусор, который игра не примет.
- Операнды — сырые `[]const u8`. Для эмиттера хватает, но `decodeOperand`
  в симуляторе разбирает их заново. После шага 5.3 посмотреть: может,
  предекод операндов вообще поднять в парсер (один разбор на оба пути).

## ExtensionPreprocessor.zig

**Хорошо:**
- Два прохода: const/alias видны до объявления — форвард-ссылки работают.
- Подстановка по словам, не по подстрокам — `MAXIMUM` не пострадает от
  `const MAX`.

**Чинить:**
- **`include` отложен сознательно** (extended syntax, для простоты) — ок.
  Проблема не в «не реализовано», а в «молча»: строка выбрасывается, и файл
  с include ассемблируется без ошибки, но неправильно. Дешёвый фикс в духе
  той же простоты: `include` → `error.IncludeNotSupported`. Честный отказ
  вместо тихой лжи, реализация — когда дойдут руки.
- Комментарии `;` и `/* */` — тоже extended, тоже отложены, тоже ок.
  Но и тут лучше «громко»: см. пункт про токенизатор.
- Подстановка одноуровневая: `const B A` не дорезолвится. Проверить, как
  у C#, и зафиксировать тестом (любое поведение, лишь бы совпадало).
- Нормализация пробелов агрессивная (всё в одиночные пробелы, пустые строки
  выкинуты) — перед диффом против C# убедиться, что C# делает так же.
- Дубликат `const X` молча перезатирается — стоит ошибку.

## Emmiter.zig

**Хорошо:**
- Тривиален и правильно таков; нормализация `+42` → `42` под C#-вывод —
  хороший пример «совместимость с оракулом важнее красоты».

**Чинить:**
- `while (i < …) i += 1` → `for (program.statements) |stmt|` — индекс не
  используется.
- (после переименования файла — см. сквозное.)

## simulate/Simulator.zig

**Хорошо:**
- `Cpu` зеркалит семантику C# (`?i32 dat` для MC4000 — изящно), clamp
  централизован, флаги предикатов названы по делу.
- **Предекод операндов** + выкинутые из потока метки — два главных
  Zig-way решения уже на месте (см. таблицу в плане, раздел 3½).
- Тесты ловят именно краевое: метка в конце файла → one-past-last.

**Чинить:**
- `decodeOperand("p15")` принимает любой индекс порта — нужен предел
  (и отдельный вид для `xN`, его пока нет вовсе — шаг 5.9).
- Дубликат метки молча перезаписывается в `labels.put` — ошибка сборки.
- Закомментированный мёртвый код в `Program.deinit` — выкинуть (метки не
  владеют памятью, и комментарий об этом полезнее трупа кода).
- `.label` резолвится строкой на исполнении — уйдёт на шаге 5.3 (известно).

## main.zig

**Хорошо:**
- Каркас субкоманд + честные `TODO` там, где пусто; `assemble` собран
  правильно (read → preprocess → parse → emit, всё с defer).

**Чинить:**
- ⚠️ `--help` и `--version` печатаются через `std.debug.print` — это
  **stderr**. `sio --version | grep …` не увидит ничего. Нормальный вывод —
  в stdout (как уже сделано в `assemble`), debug.print — только для ошибок.
- `error: {}` без контекста — связать с диагностикой из парсера (см.
  сквозное).

## build.zig

**Хорошо:**
- Версия прокинута через `b.addOptions()` — бинарь не парсит файлов в
  рантайме. Шаги test/run/bench/bench-real на месте.

**Чинить:**
- Мелочь: `createModule` с одинаковыми imports повторён для exe и tests —
  можно один модуль переиспользовать.

## Топ-3 по приоритету (если чинить до шага 5.1)

Extended syntax (`include`, `;`, `/* */`) отложен сознательно — это не баги.
Принцип, который из этого следует: **что не реализовано — должно падать с
ошибкой, а не молча выдавать мусор.** Отсюда приоритеты:

1. **«Громкие» отказы вместо тихих:** `include` → ошибка (сейчас строка
   молча выбрасывается), незнакомый символ в токенизаторе → ошибка (сейчас
   `;`-комментарий или запятая молча съедаются, `/* */` парсится как
   identifier'ы). Пока эти ошибки есть — дифф против C# гоняем на
   vanilla-подмножестве `examples/`.
2. **stdout для `--help`/`--version`** — однострочный фикс, разблокирует
   скриптовый дифф.
3. **Дубликат метки → ошибка в `build()`** — единственный «тихий» случай
   уже в ванильной семантике (сейчас `labels.put` перезаписывает).

Остальное (диагностика с координатами, число операндов, лайфтаймы) — можно вплетать
по ходу шага 5, оно не блокирует.
